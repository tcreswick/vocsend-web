What it is

vocsend moves small amounts of data from one device to another as sound. One side plays it; the other hears it. It works between phones, laptops and desktops, in any combination, and with the command-line version on a server with no screen.

It is for the small things that so often need to cross a gap: a public key, a certificate, a signature, a Wi-Fi password, a one-time code. It is slow by network standards, up to about 100 bits per second, which is plenty for those.

Why it exists

Two machines, no connection

An air-gapped machine is one kept off every network on purpose. Getting even a few hundred bytes onto or off it usually means hunting for a USB stick that you then have to trust. Other machines are simply awkward: different networks, no shared drive, no cable to hand.

Modern microphones break the obvious answer

Sound is the natural bridge, and tools for sending data as sound have existed for decades. But microphones, drivers and operating systems now apply noise suppression, echo cancellation and automatic gain by default. They keep speech and remove everything else, and a data signal is "everything else". On a lot of current hardware the traditional tools simply do not work.

How it works

vocsend uses vocal-style encoding: it sounds enough like a voice that noise suppression lets it through.

  1. The data rides on pitch. The message becomes a string of very short syllables, each sung at one steady pitch from a small set. A room changes loudness and tone, but it cannot move a frequency, so pitch arrives intact.
  2. Everything else changes, and means nothing. The vowel, the way each syllable starts, how bright and how loud it is: all of it varies from one syllable to the next in a fixed pattern. A noise suppressor removes whatever holds still. This never does.
  3. Errors are repaired. Every block carries a checksum and error correction. Nothing is shown unless it verifies, and both sides display a short fingerprint you can compare.

Levels: not just speed

There are ten levels. Level 10 is the fastest, but the level changes much more than the speed. Lower levels use fewer pitches, spaced further apart, in longer syllables, with more error correction. The signal itself becomes simpler and easier to hear, which is what gets it through a noisy room, a tinny speaker or an aggressive microphone.

When receiving, there is nothing to choose: the level is announced at the start of every transmission and picked up automatically. With negotiate switched on, the two devices try the levels and settle on the fastest one that works.

On a computer or a server

The same protocol runs from a terminal, so a phone can talk to a machine with no browser at all.

Speed test

One device plays a known burst at each level, over and over; the other shows how each one arrived. Use it to find the fastest level a pair of devices can manage in a particular spot, and to experiment: move them, turn the volume up or down, and watch the table change.

Run it on two phones, or with a computer on the other end: this page, or vocsend tx test and vocsend rx test from the command line. Each direction is separate, so test the way you intend to send.
